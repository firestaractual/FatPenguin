# Fat Penguin: notes for Claude

Mobile 3D game in **Godot 4.7.2, GDScript, Mobile renderer**. The design lives in `docs/`; read `docs/GDD.md` before changing gameplay.

## Ground rules

- **Balance numbers live in one place:** `tuning/penguin_tuning.gd` (the class) and `tuning/penguin_tuning_default.tres` (the values), mirrored in `docs/TUNING.md`. Fish species work the same way: `tuning/fish_species.gd` (the class) and `tuning/fish/*.tres` (one per species), NPC penguins too (`tuning/npc_tuning.gd`, `tuning/npc_default.tres`), and so do predators: `tuning/predator_tuning.gd`, `tuning/pod_tuning.gd`, `tuning/pod_attack_tuning.gd` (+ one subclass per attack) and `tuning/predators/*.tres`. Don't hard-code tuning values in gameplay scripts.
- **Predators are built from shared parts; add new kinds the same way.** Every predator is `actors/predators/predator.gd` (`Predator`: swimming, sight, targeting, hunger, feeding, the lunge and its warnings); a kind is a `PredatorTuning` resource plus a scene with a `Model` node. Pods (`PredatorPod`) keep formation and run group attacks; an attack is a `PodAttack` subclass (on the ice `EdgeAttack`: `WaveAttack`, `RamAttack`; in the water `CutOffAttack`, `CarouselAttack`) plus a `PodAttackTuning` resource listed in the pod's `PodTuning.attacks`, and attacks chain into traps with `chains_into`. Pods give orders with `Predator.order_move()` and `order_strike()`. Ice that attacks can tip is marked with `TippableIce` (`levels/tippable_ice.gd`); questions about where the ice ends go through `IceEdges` (`levels/ice_edges.gd`). Levels spawn predators from `PredatorSpawn` entries through a `PredatorSpawner`. Shoves from outside (waves, jolts) go through `Penguin.push()`, currents (bubbles) through `Penguin.drift()`, and stuns through `Penguin.stun()`. What a catch does is up to the level's `GameMode` (`core/game_mode.gd`; with none, the movement toy's rule: respawn), not the penguin or the predator.
- **Bergs are built from shared parts too.** Every berg extends `IceBerg` (`levels/bergs/ice_berg.gd`): it builds its own collision and meshes in code from `box`, `slope`, `steps`, `keel` (with an optional tunnel) and `frustum`, and answers `reach()`, `top_height()`, `waddle_spot()`, `exits()` (ways out of the water, with `climb` waypoints) and `tunnels()`. Predators patrol round bergs, fish keep clear of them and NPCs live on them through that API, so a new berg is a short script. Keep new kinds true to real ice: a real shape, its real height-to-draft ratio (`IceBerg.draft_for()`), 6 m or less above water, and a way out of the water.
- **A penguin is a body plus parts.** `Penguin` (`actors/penguin/penguin.gd`) is the body and its movement rules. Its stick and button come from a `PenguinInput` (`Penguin.input`): `PlayerInput` (one per player, `player_number` 1–4; players 2–4 get their own copies of the actions bound to one gamepad each, so local coop works), `BrainInput` (follows `wish_dir`), or the base class for a dummy. Energy and air and their rules live in `PenguinVitals` (`Penguin.vitals`; `energy`, `air`, `drain_mult` and `infinite_energy` on the penguin are its numbers): pay for a move with `vitals.spend()`, and put the energy loop, the waddle's drain and exhaustion there. How it looks is `PenguinLook`, the script on the `Model` node: it reads the penguin (state, public getters, `splashed` / `feathers_flew`) and never moves it, so a real model can bring its own look script.
- **NPC penguins are ordinary penguins with a `PenguinBrain` child** (`actors/penguin/penguin_brain.gd`). The brain steers through `Penguin.wish_dir` / `wish_action` / `wish_brake` (with `brain_controlled = true`, which gives the penguin a `BrainInput`), the same inputs a stick gives, so NPCs follow the player's movement rules; don't move them any other way. The "by hand" methods (`place()`, `force_state()`, `set_facing()`, ...) are for levels and tests only.
- **Design changes get a log entry:** add a dated entry at the top of `docs/DECISIONS.md`, and update the status tags in `docs/GDD.md` (`[Locked]` / `[Proposed]` / `[Open]`).
- **Naming:** "waddle" means the safe group of penguins on the ice. The slow on-ice gait is called **walk** in code (`State.WALK`, `walk_speed`) so the two don't get confused.
- **Water line:** the water surface is `y = 0` (`GameWorld.WATER_LEVEL`, `core/game_world.gd`). Anything below is water.
- **Penguin body:** a sphere collider that never rotates. Only the `Model` node turns and changes width, so physics stays simple and art can be swapped freely.
- **Physics layers:** layer 1 is the world (ice, seafloor), layer 2 is penguins, layer 3 is predators (`GameWorld.WORLD_LAYER`, `PENGUIN_LAYER`, `PREDATOR_LAYER`; named in Project Settings too). Ground and ledge probes ray-cast against the world layer only, so penguins never mistake each other for ice. Predators collide with the world only; their catches are by distance, not collision.
- **Bumps:** penguin-on-penguin hits are resolved by hand in `Penguin._bump()` after every `move_and_slide` (call `_move()`, not `move_and_slide()`, in movement states). Dummies are ordinary penguins with `player_controlled = false`.
- **Input:** gameplay reads only the input actions (`move_*`, `action`), and only through `PlayerInput` (player 1 reads the shared actions; player N reads `pN_move_left` and so on). Touch controls feed the shared actions through `Input.action_press`, so don't read touch events directly in gameplay code. Tester keys (Q/E/F2/R) are handled by the debug HUD, not the penguin.
- **UI lives in `ui/`** and is styled by one theme, `ui/theme/fat_penguin_theme.tres` (set project-wide), with type variations for the kinds of thing on screen: `PrimaryButton`, `RoundButton`, `TitleLabel`, `CaptionLabel`, `HudLabel` (white with a navy outline, over the game), `Wordmark`, `PromptPanel` / `KeyChip` / `KeyChipLabel`, `DebugLabel`. Use them rather than per-node overrides. UI never uses the danger colour (ART_DIRECTION rule 2), and keeps away from oranges near it. There's no energy bar (body size is the energy display). The in-game HUD is `GameHud` (one per player's penguin); the game pauses through `PauseMenu` (`SceneTree.paused`; it and its settings run with `PROCESS_MODE_ALWAYS`); the title screen is `TitleScreen` (the main scene). Control prompts are the `PROMPTS` table in `ui/hud/control_prompts.gd`; name controls with `InputDevice.control_name()` so they match the device. HUD buttons that touches should reach go in the `touch_ui` group so the touch stick ignores them. Timers in gameplay code must stop while paused: `get_tree().create_timer(t, false)`.
- **Player settings are not tuning.** Control preferences, the hints and the debug switch live in `GameSettings` (`core/game_settings.gd`, saved to `user://settings.cfg`): `GameSettings.current().invert_pitch` and so on. Tests start from `GameSettings.use_defaults()`, which never touches the file. The debug numbers (`DebugHud`) are hidden unless `show_debug` is on (F1 flips it).
- **Typing:** use static typing throughout (`var x := ...`, typed function signatures).

## Before finishing a change

Run the headless smoke test and make sure it passes (3 times when you've touched predators or NPCs: they make random choices):

```
godot --headless --fixed-fps 60 --path . --script res://tests/movement_smoke_test.gd
```

Add `-- --only=orcas,npcs` to run only some suites (movement, bumping, fish, seals, orcas, bergs, npcs, players, ui), and `-- --seed=N` to replay a run with the seed it printed. The checks are in `tests/suites/`, one file per area, with shared helpers in `tests/smoke_suite.gd`. When you add a new movement verb, add a check for it to the right suite.

Tests drive the game through public methods only. Never `set()`, `get()` or `call()` a private member (a leading underscore) by name: `set()` on a field that no longer exists does nothing, so after a rename the check quietly stops testing instead of failing. If a test needs a hook, add a public method (see the "Placing and steering by hand" section of `Penguin`).
